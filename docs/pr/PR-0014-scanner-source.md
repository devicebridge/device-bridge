# PR-0014 Scanner Source

## Статус

Merged

---

## Цель

Добавить первый реальный источник данных — Scanner Source.

Scanner получает данные от внешнего сканера и публикует их в общий Bus. После публикации сообщение проходит существующий pipeline: Bus → Bridge → Hub → WebSocket → Web Client.

---

## Архитектура

```
Scanner
   ↓
Bus
   ↓
Bridge
   ↓
Hub
   ↓
WebSocket
```

---

## Ответственность Scanner

Scanner:

- получает данные от внешнего источника;
- формирует `Message`;
- публикует сообщение в общий Bus.

Scanner НЕ:

- отправляет данные WebSocket-клиентам;
- работает с HTTP;
- содержит бизнес-логику;
- взаимодействует с Hub напрямую.

---

## Выполненные изменения

Создан пакет:

```
internal/source/scanner
```

Добавлены типы:

```go
type Input struct {
    Value string
    Err   error
}

type Scanner struct
```

Добавлены методы:

- `New(sourceID string, input <-chan Input, bus *bus.Bus) *Scanner`
- `Scanner.Run(chan<- message.Message) error`

Scanner реализует интерфейс `source.Source`.

---

## Принятые решения

- Scanner получает зависимости (sourceID, канал ввода, Bus) через конструктор.
- Входной канал имеет тип `chan Input`, где `Input` содержит значение и возможную ошибку.
- Пустые значения (`Value == ""`) не публикуются — пропускаются.
- Timestamp формируется при создании каждого Message через `time.Now().UnixMilli()`.
- Ошибки входного канала (`Input.Err != nil`) возвращаются из `Run` и прекращают обработку.
- Scanner публикует сообщения напрямую в Bus через `bus.Publish()`.
- Scanner не содержит глобальных переменных.
- Scanner не читает environment variables.
- Физический сканер не используется — данные поступают через абстрактный канал `Input`.
- Конкретный транспорт физического сканера будет добавлен отдельным этапом.

---

## Тестовый ввод

В PR-0014 Scanner использует канал `<-chan Input` как источник данных. Это позволяет тестировать Source без физического устройства.

Физический транспорт сканера (USB HID, Serial, COM-порт, Bluetooth) не реализуется в данном PR — он будет добавлен отдельно, когда будет выбран конкретный способ подключения.

## Совместимость

Изменений, нарушающих обратную совместимость, нет.

Дополнительные внешние зависимости не добавлены.

---

## Что намеренно НЕ входит

В данный PR не входят:

- USB Scanner / HID / Serial / COM / Bluetooth;
- конкретная модель сканера;
- конкретный драйвер;
- автоматическое обнаружение сканера;
- reconnect физического устройства;
- несколько сканеров одновременно;
- бизнес-логика (GS1, Честный знак, Wildberries, 1С);
- хранение истории сканирования;
- database;
- WebSocket-specific код;
- HTTP-specific код.

---

## Результат

Проект получил первый реальный Source — Scanner. Scanner публикует сообщения в Bus без зависимости от HTTP/WebSocket/Hub. Pipeline `Scanner → Bus → Bridge → Hub → WebSocket` готов к интеграции.
